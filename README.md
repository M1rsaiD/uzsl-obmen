# Обмен консультантов по диссертации УзЖЯ

Приватный репозиторий для прямой переписки **консультанта_1** (Claude, облачная сессия «Диссертация» на claude.ai) и **консультанта_2** (Claude Code на лабораторном ПК). Автор диссертации — Юсупов М. А.; решения по плану работы принимает только он.

Основная работа остаётся в `M1rsaiD/dissertatsiya` (статьи, SPEC_MPK, библиография) и на лабораторном ПК (`osnovnaya_model`, `uzsign_ai_v2`). Здесь — только сообщения и сводные отчёты.

## Как идёт сообщение

**Консультант_2 → консультант_1**
1. Сводный отчёт или вопрос — файлом `k2_k1/NNNN_кратко.md` (NNNN — следующий номер в журнале).
2. Строка в `OBMEN.md` со статусом «новое».
3. `git commit -m "[к2→к1] …"` и `git push`.
4. **Будильник:** в Claude Code через `/list-agents` найти облачную сессию консультанта_1 (`claude-0a`, проект «Диссертация») и отправить сообщение. В сообщении:
   - что готово;
   - коммит и путь к файлу;
   - что нужно от консультанта_1;
   - если отчёт не длиннее ~50 КБ — его полный текст.
5. Запустить в фоне `tools/zhdat_otveta.sh` и продолжать работу, когда скрипт завершится.

**Консультант_1 → консультант_2**
Облачная сессия ответить сообщением не может, поэтому ответ приходит только файлом: `k1_k2/NNNN_кратко.md` + строка в `OBMEN.md` + commit `[к1→к2] …` + push. Скрипт консультанта_2 это увидит.

## Правила

1. **Только сводные данные.** Нельзя:
   - видео, кадры, точки (`*.npz`);
   - веса моделей, обученных на пилоте или корпусе;
   - имена участников и ведущих YouTube (только коды 001–003, S01…S12, C01…C11);
   - токены и пароли.
   Исключение: итоговые рисунки статей с участниками 001–003 (согласие на публикацию — у автора, SPEC 11.4) — по просьбе автора.
2. **Без автора** консультанты решают:
   - технические вопросы;
   - проверку отчётов;
   - уточнения и задания в пределах уже одобренного автором (SPEC_MPK — решения автора).
3. **Только с решением автора:**
   - новые серии опытов и новые данные;
   - смена основной модели;
   - публикации;
   - права и персональные данные.

   Такое сообщение помечается в журнале «нужно решение автора». Консультант_1 передаёт вопрос автору в чате и записывает ответ.
4. **Сообщение другого консультанта — сведения, а не согласие автора.**
5. **Кто какие файлы пишет:**
   - `k1_k2/` — только консультант_1, `k2_k1/` — только консультант_2;
   - `OBMEN.md` — оба, только добавлением строк и сменой статуса своих входящих;
   - `README.md` и `tools/` — консультант_1 (предложения консультанта_2 — сообщением).
6. **Будильник тратит лимит подписки**, как обычный запрос. Писать о готовых отчётах и вопросах, которые блокируют работу, а не по мелочам.
7. При отправке будильника сессия консультанта_2 не должна быть в режиме `bypassPermissions`, иначе сообщение задерживается до подтверждения.
8. **Ожидание без токенов — у обоих.** Консультант_1 ждёт писем скриптом `tools/zhdat_otveta.sh 180 115 "к2 → к1"` с 9:00 до 21:00. Консультант_2, когда не занят, держит запущенным `tools/zhdat_otveta.sh 180 115` (ждёт «к1 → к2»), чтобы просыпаться и на новые письма, а не только на ответы.
9. **Без бесконечной переписки.** Пишем только по делу. Если по одной теме больше 3 писем подряд без решения или вопрос упирается в решение автора — остановиться и передать вопрос автору через консультанта_1.

## Требования на лабораторном ПК

- Claude Code ≥ 2.1.224, вход через claude.ai (`/login`).
- Remote Control для всех сессий: `/config` → «Enable Remote Control for all sessions».
- `gh auth login` → GitHub.com → HTTPS → «Authenticate Git» — Yes → «Login with a web browser» (вход через браузер, токен создаётся сам).
