## 3. U01b
### 3.1. Определение (0153 разд. 3.2 с правками к1 0136 разд. 5; принято к3 0039 разд. 5)
Термин и 84 признака — из `a302d0f` 4.2, строки 289–290: «кисть в собственной системе координат (начало — запястье, масштаб — ладонь;
84 признака `preprocess_pose` идеи 3)». Ладонь, координаты и окно взяты из решений по U04 (к1 0123 п. 15, к3 0031 п. 15; `a302d0f`
4.3, строки 377–394).

**Запись.** После `sohn.augment` при обучении, на оценке — как есть. Это x[t, i] ∈ ℝ², t < T, i — 122 точки (118 Sohn + поза; поза не
используется, 3.2). Кроме того:
- a = H/W записи (`Recs.aspect`);
- T′ = min(T; 384) — первые 384 кадра (MAX_LEN, `sohn.py`:35), те же, что идут во вход.

**Формулы.** Кисть h ∈ {Л, П}; точка j = 0…20 в порядке MediaPipe (Л — `LHAND` 468–488, П — `RHAND` 522–542, `sohn.py`:30–31; 0 —
запястье, 9 — основание среднего пальца).
- p(t, j) = (x(t, j); a · y(t, j)) — изотропные координаты, до нормировки Sohn;
- K_h = {t < T′ : есть p(t, 0) и p(t, 9)};
- ладонь ℓ_h — медиана ‖p(t, 9) − p(t, 0)‖ по t ∈ K_h. Это то же выражение, что ладонь U04 (`hand_feats`, `sohn.py`:270–271). Если
  K_h пусто, ℓ_h нет;
- u_h(t, j) = (p(t, j) − p(t, 0)) / ℓ_h ∈ ℝ² — точка минус запястье этой кисти в этом кадре, делённое на ладонь;
- NaN и ±∞ → 0, затем обрезка [−10; 10] (как `hand_feats`, `sohn.py`:280). Значит, нет точки j или запястья в кадре t → 0; нет ℓ_h →
  все 42 столбца кисти = 0 во всех кадрах (к1 0136 разд. 5, правка 1: «42», а не «84»);
- столбцы кисти: u_h(t, 0), …, u_h(t, 20), у каждой точки (x, y) — 42 столбца;
- **вход: [Sohn 708 | u_Л 42 | u_П 42] = 792 столбца**. Если есть U04, её столбцы стоят перед U01b.
- u_h(t, 0) ≡ (0; 0). **4 из 84 столбцов («запястье − запястье», x и y на кисть) тождественно 0** — оставлены и записаны (к1 0136
  разд. 5, правка 2; к3 0039 разд. 5).

### 3.5. Число плеч и риск: формулы, числа, печать
- **Плеч в серии:**

- **Как `a302d0f` считает риск одного шага** (угроза 1, строки 776–782; `runs/UZSOHN/revision_r2/false_accept_sim.py`, строки 8–22,
  и `false_accept_sim_discrete.py`). Обозначения:
  - s(j, k) = m(j, k) + ε(j, k) — счёт плеча j на V_k (j = 0 — контроль);
  - ε(j, k) ~ N(0; σ_k²) — независим по j и k;
  - Δ(j, k) = s(j, k) − s(0, k).
- **Событие «шаг принят»:** A_j = {(1/10) Σ_k Δ(j, k) ≥ THR} ∩ {#{k : Δ(j, k) > 0} ≥ 6}, THR = max(1; δ) = 1,0082.
- **σ_k — три модели:**
  - M1: σ_k = σ̂_k — СКО трёх затравок базы `alluz_pre` на S_k (ddof 1);
  - M2: σ̂_k × 0,512 / 0,662 — подогнано под наблюдённое СКО macro трёх затравок;
  - M3: σ_k² = c · p_k (1 − p_k) / n_k · 10⁴, c = 0,219 — биномиальная форма с общим множителем;
  - M1 и M2 ещё и в целых записях V_k: шум в записях, ничья Δ = 0 — «не лучше».
- **Риск одного шага:** α₁ = P(A_j | у плеча и контроля m одинаковы на всех V_k).
- **Накопленный по серии:** α_n = P(A_1 ∪ … ∪ A_n | у всех n плеч эффект нулевой), n = 5.

### 5.2. Что считается
- θ_SWA = (θ₂₀₀ + θ₂₁₀ + … + θ₂₉₀ + θ₃₀₀) / 11, θ₃₀₀ — `last.pt`; равное среднее всех параметров, в т. ч. аффинных `MaskedBN` и
  классификатора.
- Бегущие средние — не среднее, а пересчёт (5.3).

### 5.3. Пересчёт `MaskedBN` — своим кодом
**Почему своим кодом.** `torch.optim.swa_utils.update_bn` берёт только `_BatchNorm` (`swa_utils.py`:405), сбрасывает их
(`reset_running_stats`, :406) и ставит `momentum = None` (:415) — к3 0039 разд. 6; к2 проверил на ПК в установленном torch
2.14.1+cu132. `MaskedBN(nn.Module)` — `sohn.py`:362, его `update_bn` пропустит (тест `test_update_bn_skips_maskedbn`, `6430ac5`).

**Три параметра к3 (0039 разд. 6; к1 0137 — за):**
1. перед проходом — сброс: `running_mean` = 0, `running_var` = 1, `acc` пуст;
2. равное накопленное среднее по **всем** частям прохода, без веса по числу шагов маски: μ = (1/P) Σ_p μ_p, σ² = (1/P) Σ_p σ²_p
   (в обучении `commit` — равное среднее по частям шага, затем EMA 0,95: `sohn.py`:388–394);
3. μ_p и σ²_p — как в `forward`: по шагам маски внутри части, дисперсия смещённая (`sohn.py`:379–383). Итог — среднее внутричастных
   дисперсий без разброса средних между частями, как у `update_bn`.

**Задаёт к2 (так в коде `6430ac5`, умолчания `uzsohn_u30_swa.py`; на сверку):**
- **данные** — обучающие записи прогона отбора этого фолда: обучение фолда без S_k и без V_k (`m13_train.py`:659). Сверка: их число =
  `n_train` в `metrics.json`;
- **аугментация** обучения `sohn.augment` — как `a302d0f` разд. 6, строки 598–605. Без аугментации ветка Sohn опоры U02 не
  срабатывает (0 из 7 815 записей против 6,1–6,4 % при обучении), и пересчёт сдвигает BN у плеч по-разному;
- **порядок и аугментация — генераторы обучения прогона:** порядок — `default_rng([48, 7]).permutation(train)`, основа порядка
  `Stream` обучения (`m13_train.py`:219–220), без буфера перемешивания (`pass_order`, `uzsohn_u30_swa.py`:95–99; проход один, флага
  числа проходов нет). Аугментация записи на позиции pos прохода — как в обучении, `m13_train.AugSet`: `default_rng([48, pos])`,
  тот же `sohn.augment` и та же предобработка входа (`bn_parts`, строки 102–108). Как и в обучении, у позиции 7 генератор тот же,
  что у порядка (`default_rng([48, 7])`); на моменты BN это не влияет. Случайный порядок нужен ради п. 3 к3: части должны быть
  случайными выборками, как пакеты обучения;
- **части** — по 64 записи подряд, как `collate_parts` (8 × 64 = 512; `m13_train.py`:55, 234). Неполная последняя часть (n mod 64)
  не берётся;
- **проходов** — один, как `update_bn`;
- **режим** — `model.train()`, как `update_bn`: dropout блоков 0,2 действует, как при обучении (`sohn.py`:404–410). Late dropout стоит
  после пулинга и на BN не влияет (`sohn.py`:642), в коде он выключен (`uzsohn_u30_swa.py`:75). Перед каждым проходом — и для
  «last + пересчёт», и для SWA — `torch.manual_seed(48)` (строка 77);
- **AWP нет:** AWP — часть шага обучения, не вывода;
- **ЦП, float32**, без autocast — одинаково для всех столбцов 5.4;
- **парность:** «SWA» и «last + пересчёт» получают одни входы и одни маски dropout.
