# UzSohn: идеи улучшения по литературе (обзор, 07.11.2026)

Консультант_2. Только чтение и веб-поиск; ГП не использовался, прогонов нет. Числа ниже взяты **из первоисточников**,
наши ожидания для УзЖЯ — **качественные** (низк./сред./выс.): перенос чужих приростов на LOSO УзЖЯ (7 815 зап., 3 531 кл.,
12 исп., macro top-1 ≈ 30 %) не делается.

**Как проверялось.** Описания решений Kaggle получены из исходного текста описания (поле `rawMarkdown` через внутренний
API Kaggle `discussions.DiscussionsService/GetForumTopicById`; веб-страница Kaggle без JS не открывается). Статьи arXiv
прочитаны по PDF (alphaXiv). «Проверено» = число/утверждение найдено в первоисточнике дословно. Метрики GISLR — точность
(доля верных) на скрытом тесте; «CV» — внутренняя проверка команды, у большинства — деление по участникам.

## 1. Базовая точка: что говорит сам Sohn (1-е место GISLR)

Источник: <https://www.kaggle.com/competitions/asl-signs/discussion/406684> (проверено).
- 1D-CNN лучше чистого трансформера; переход 8-слойной CNN 192d → (3 conv + 1 transformer)×2 дал **+0.01** CV и LB.
- Одиночная модель: CV 0.80 (5 фолдов по участникам), public LB 0.80, private 0.88; ансамбль 4 затравок — LB 0.81.
- Регуляризация (drop path 0.2, dropout 0.8 после GAP, AWP λ=0.2; AWP и dropout с 15-й эпохи): «удаление любого заметно
  ухудшает» (чисел нет).
- Признаки: лаг 1 и 2 (лаг > 2 «почти не помогал»); нормализация по точке носа 17.
- **Не сработало у него:** GCN; сложные аугментации (по углам/расстояниям, grid distortion); CutMix/MixUp (не смог задать
  метку при разной длине); дистилляция (не успел); модель ×4 (384d, 16 слоёв) — «немного хуже».

Не рекомендуется (по литературе): увеличение модели (у Sohn ×4 хуже; у нас данных меньше), ручные графовые признаки и
доп. точки глаз (6-е), TTA (1-е FS: не помог; 28-е: +0.000x), обучение из ASL-данных Kaggle (у нас уже не установлено).

## 5. Топ-5 рекомендаций

1. **Гетерогенный ансамбль по уже экспортированным LOSO-логитам** (Sohn + A1 + SL-GCN, сложение логитов, веса — по
   внутренней валидации, не по тесту). Цена ≈ 0 ГП (`runs/TURNIR/preds`). Самый дешёвый кандидат с наибольшим ожиданием: в
   GISLR ансамбли разных семейств давали +0.005…0.01 при сильных одиночных моделях; у нас ошибки на новом человеке разнятся
   сильнее. Ограничение: вывод ×3 по времени (демо/телефон).
2. **Аугментации «части от того же класса» + вырезки по частям/пальцам/времени** (идеи 2–3) в загрузчике Sohn. ≈ 1×.
   Это ровно наш случай: мало записей на класс, разные исполнители и источники; синтез «руки от одного, лица от другого»
   моделирует нового исполнителя. Отбирать по **полному** 300-эпохному прогону (урок 2-го места FS: на коротких прогонах
   полезные аугментации выглядят вредными).
3. **Косинусная/прототипная голова + сбалансированный батч (k×2) + supervised-контрастная вспом. потеря** (идеи 4, 10).
   ≈ 1.3–1.5×. Совпадает с нашим принятым NCM (M10) и даёт эмбеддинг для «не знаю» и добавления слов без переобучения.
   Литература: SignSeek (контраст + баланс), 4-е и 28-е GISLR (нормированные головы). Оговорка: сила эффекта у SignSeek — на
   266K записей, у капстоуна (+13 п. п.) — без рецензии.
4. **Языковое сглаживание меток по глоссам (fastText uz/ru) с учётом синонимов** (идея 5). ≈ 1×, подготовка на ЦП.
   NLA-SLR: +1.22 top-1, больше всего на близких по смыслу жестах (50.5 → 64.4) — у нас синонимы и варианты глосс есть
   прямо в корпусе. Требует таблицы глосс → вектор (fastText cc.uz/cc.ru; наличие узбекской модели — проверить при
   предрегистрации).
5. **Шум меток: CleanLab по LOSO OOF → список на ручную проверку автором; OUSM в обучении** (идея 6). CleanLab — 0 ГП,
   OUSM ≈ 1×. Прирост в GISLR скромный (+0.003), но для корпуса это ещё и чистка данных (сочетается с проверкой 300 меток).
   Автоматически не удалять: при 1–2 записях на класс удаление = потеря класса.

Следом (сред. цена/ожидание): точки рук/плеч позы ко входу Sohn (идея 7) и нормализация по частям (8) — обе ≈ 1×, но
частично уже есть в A1; разумно проверить на Sohn одним предрегистрированным прогоном.
