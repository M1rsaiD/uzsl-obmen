## 2. Идеи

### U39. Группы VSSigns Logos в метках предобучения Slovo

**Тезис.** Предобучаем Sohn на Slovo + Bukva по рецепту S+B, но глоссы Slovo из одной группы VSSign объединяем в одну метку. Группы берём из `data/Logos/class_ids.tsv` (открытый файл репозитория Logos, Apache-2.0). Bukva и дообучение на ALL-UZ — без изменений. Рычаг один: метки предобучения.

**Слабость.** Мало записей на класс ([Д], разд. 1):
- корзина 1 — 22,8 % теста, Sohn 5,87 %;
- корзина 2–4 — 44,6 % теста, Sohn 23,28 %.

Измеренный рычаг — перенос кодировщика: +14,66 [+11,24; +18,59], 10/10 (С1). U39 добивается более переносимого кодировщика без новых данных.

**Лучший вариант 2024–2026.** Logos (Ovodov и др., EMNLP 2025; arXiv 2505.10481 v2). Файл: [к2] `2025_ovodov_logos_v2_key_sections.md`, id 1HeOv8Q3nTrsrT468HF22IOewA0GQQGbM. Табл. 8, стр. 9 — предобучение на группах против предобучения без групп:

| перенос на | с группами | без групп | Δ |
|---|---|---|---|
| WLASL, 3-shot | 54,10 | 51,60 | +2,50 |
| AUTSL, 3-shot | 83,99 | 82,38 | +1,61 |
| WLASL, полный | 62,44 | 60,74 | +1,70 |
| AUTSL, полный | 97,25 | 96,79 | +0,46 |

- **Новее не найдено.** Искал: Диск — нет; интернет — «visually similar signs grouping pretraining» (2025–2026): только Logos. В Sigma 2025/2026 ([lib] id 1cw5a8KzzcTxK3A0CJmmsJrnridJjs2YI, стр. 19) «visually similar but semantically different» — только качественные примеры, группировки нет.
- **Почему берём этот вариант.** Это единственная проверенная работа. Нужный файл групп открыт, а Slovo входит в Logos (статья, стр. 5): группы размечены в том же словаре.

**Наш подсчёт (ур. 2, прил. А, 09.11):**
- в Slovo 998 различных глосс (нижний регистр, без `no_event`);
- 987 из них совпали с леммами Logos и попали в 808 групп;
- в 120 группах по ≥ 2 глоссы Slovo, всего в них 299 глосс;
- итог: метки Slovo 998 → 819 (−18 %).

**Условия.**

| | Logos | у нас |
|---|---|---|
| модель | MViTv2, RGB | Sohn, 118 точек MediaPipe |
| объём предобучения | ≈ 161 тыс. записей | 23 560 (S + B) |
| цель | WLASL / AUTSL | УзЖЯ, LOSO 10 |
| статистика | 1 прогон, без ДИ | 3 затравки, 99 % ДИ |

**Уровень:** 4.

**Сильнейший контрдовод против себя.** Прирост у Logos — +0,46…+2,50 по одному прогону, без ДИ. Это сравнимо с разбросом затравок: у нас Sohn×3 − Sohn = +1,05 [+0,07; +2,05] ([Д], разд. 6). Есть и риск по механизму: 54,6 % ошибок Sohn — пары «близки по обоим» ([Д], разд. 3). Если объединить похожие жесты в предобучении, кодировщик может хуже различать как раз такие пары.

**Как проверить:**
1. Зонд на внутреннем V_k. Кодировщик заморожен, сверху голова, обучение на ≤ 3 записях класса из обучения фолда — аналог табл. 8. Два кодировщика: «с группами» и «без групп», 3 затравки. Порог — в предрегистрации.
2. Если зонд не отрицательный — пара в LOSO. Главная строка — macro top-1. Вторичная — точность на парах «близки по обоим».

**Цена:**
- предобучение S + B: 13 800 шагов, 10 450 с на затравку (`osnovnaya_model/runs/UzSohn/sb/all/seed42/metrics.json`); 3 затравки ≈ 8,7 процесс-ч, ≈ 2,9 ч по часам;
- зонд ≈ 0,1 ГП-ч (оценка);
- LOSO 30 прогонов ≈ 56,62 процесс-ГП-ч, 62,2 млн примеров (`U33_tables.md`, строка Sohn · Sohn).

### U38. Голова УзЖЯ из головы РЖЯ по переводу глосс

**Тезис.** В дообучении Sohn на ALL-UZ голова сейчас новая, случайная. Если у класса УзЖЯ есть пара в Slovo или Bukva по словарю перевода, его строку весов и смещение копируем из головы S+B. Остальные классы — как сейчас. Пары задаёт словарь, не тест; список фиксируется в предрегистрации.

**Слабость.** Корзина 1: 931 запись теста, Sohn 5,87 %. Корзина 2–4: 23,28 % ([Д], разд. 1).

**Лучший вариант 2024–2026.** Logos v2, табл. 5, стр. 8 (тот же файл [к2]). Замороженный кодировщик Logos и одно отображение меток РЖЯ → целевой язык, без обучения головы: AUTSL 65,78, WLASL 23,63. С обученной головой — 97,25 и 62,44. Вывод: голова РЖЯ сама переносит часть знания даже на неродственные языки, но слабее обученной. Поэтому берём её только как начальную точку, а не вместо обучения.
- **Новее не найдено.** Искал: Диск — нет; интернет — «cross-lingual sign recognition classifier head initialization 2025». Нашлись:
  - Wei & Chen 2023 (сопоставление знаков между языками, для непрерывного распознавания) — старше Logos; на Диск не загружал, как довод не использую;
  - arXiv 2603.03316 (2026, перенос иконичных знаков) — только аннотация, ур. 6, на Диск не загружал и как довод не использую.

**Наш подсчёт покрытия (ур. 2, прил. А).** Это нижняя граница, взята только по имеющейся карте `datasets/gloss_map.json`, ветка ru→uz:
- с Slovo: 190 классов ALL-UZ из 3 531 (5,4 %), 860 записей из 7 815 (11,0 %);
- с Bukva: 29 кириллических букв, 62 записи.

**Условия.** Logos: RGB, перенос на неродственные ASL и TSL. У нас: Sohn по точкам, УзЖЯ (близость к РЖЯ не измерена).

**Уровень:** 4 (довод о механизме); покрытие — ур. 2.

**Сильнейший контрдовод против себя.**
- Покрытие мало: даже при сильном эффекте на 5,4 % классов вклад в macro top-1 ограничен.
- «Ложные друзья»: перевод тот же, а жест другой. Для классов с одной записью неверная начальная точка может навредить.
- 300 эпох рецепта Sohn могут стереть начальную точку.

**Как проверить, без S_k (п. 5.2).**
1. ЦП, 0 ГП. Модель S+B (затравки 42–44) без дообучения прогоняем только на записях, которые всегда в обучении: 1 822 записи из трёх источников, в тесте их нет ([Д], разд. 5). Считаем top-1 среди сопоставленных классов S+B и сравниваем со случайным уровнем.
2. Порог снятия задаётся до счёта.
3. Если порог пройден — пара в LOSO. Вторично — разбивка по корзинам 1 и 2–4.

**Цена:**
- ЦП: 1 822 × 3 модели × 3,84 мс ≈ 21 с вывода (`ALLUZ_inference_cost.md`, Sohn 3,841 мс на запись) плюс сборка карты;
- LOSO: 56,62 процесс-ГП-ч; нового предобучения не нужно.
- Расширение словаря перевода — работа автора, решение за ним (п. 7.2).

### U36. Готовый кодировщик SHuBERT

**Тезис.** Берём SSL-кодировщик SHuBERT (86 млн параметров; ≈ 984 ч ASL, YouTube-ASL). Дообучение по их рецепту ISLR: LoRA ранга 1 + голова. ALL-UZ, LOSO, 3 затравки. Подаём **отдельной строкой «система против системы»**, против Sohn 29,79 — как U33: меняются и вход, и предобучение.
- Отличие от U26 (самообучение на наших неразмеченных точках): кодировщик готовый, на чужих данных, с RGB-вырезами.
- Отличие от U25: обучения с учителем на ASL нет.

**Слабость.**
- Корзины 1 и 2–4 ([Д], разд. 1).
- Новый человек и новая съёмка: YouTube 25,11 % против пилота 36,3 % ([Д], разд. 5).

**Лучший вариант 2024–2026.** SHuBERT (Gueuwou и др., ACL 2025; arXiv 2411.16765 v3). Текст: [lib] `2025_gueuwou_shubert.pdf`; `.md` id 1onMytmZN6tYaRegjyJkIEoM8672IWYoG, `.txt` id 15NH3ZxsFwixjx3iN75Pqawd_-exPKzOE (v3, страницы совпадают). - SignSeek 2026 — табл. 6: ASL Citizen top-1 74,7; весов нет;

**Условия.**

| | SHuBERT | у нас |
|---|---|---|
| язык | ASL | УзЖЯ |
| записей на класс | ≈ 30 (ASL Citizen) | ≤ 4 у 67 % теста |

Малое число записей в статье не проверялось.

**Уровень:** 4.

**Применимость к нашему конвейеру:**
- Поток позы тела можно собрать из наших точек MediaPipe.
- Потоки кистей и лица — это признаки DINOv2 по вырезам из **видео**. Видео корпуса лежат на ПК; что они есть для всех 7 815 записей, не проверено. Лицо обрабатывает программа, кадры никто не смотрит; признаки — только на ПК (п. 6.1).
- Телефон — нет.

**Сильнейший контрдовод против себя.** На том же тесте ASL Citizen модель только на точках MediaPipe, обученная с учителем без SSL, сильнее: PoseFormer, Rec@1 0,751 (Vandendriessche 2025, табл. 2, стр. 7; [к2] id 1wM9EuSAqtAzBv8qooJDlaSocWBt4Bx7D), против 0,65 у SHuBERT. Уровни 5 против 4, протоколы разные. Значит, сам по себе готовый SSL-кодировщик не обходит сильную модель по точкам, а Sohn — такая модель (того же семейства: свёртки по времени + трансформер). Второй риск — как в U25: язык предобучения ASL, дактиль может проседать.

1. Зонд на внутреннем V_k, 3 фолда. Замороженные признаки SHuBERT (взвешенная сумма слоёв, их табл. 6) + логистическая регрессия **против** замороженных признаков Sohn S+B + тот же зонд.
2. Порог «идти дальше» — в предрегистрации.
3. Вторичное правило U25: дактиль не хуже базы.

**Цена (оценка, не замер):**
- ALL-UZ: 729 858 кадров (кэш `cache/M13/alluz.npz`), SHuBERT берёт ≈ 15 к/с (статья, стр. 6) — около половины;
- MediaPipe и вырезы ≈ 1–2 ч ЦП (по нашим ≈ 218 к/с Э0);
- DINOv2 < 0,5 ГП-ч; зонд ≈ 0,1 ГП-ч;
- LOSO с LoRA, 30 прогонов, 86 млн параметров — 5–15 ГП-ч.

**Как проверить:**

2. До любых прогонов на Logos — доза на том, что есть (ур. 1). Предобучение Sohn на 50 % исполнителей Slovo против 100 %, равное число шагов, зонд на V_k (как в U36). Если 50 → 100 % даёт ≈ 0, ожидание от Logos малое.

**Цена:**
- Э0: 221,4 ч × 30 к/с ≈ 23,9 млн кадров / 218 к/с ≈ 30 ч ЦП (пересчёт, ур. 2);
- предобучение: обучающих ≈ 161 тыс. (80,7 % × 199 668) против 23 560 у S + B, ≈ ×6,8. При тех же 300 эпохах ≈ 20 ч на затравку, 3 затравки ≈ 60 процесс-ч;
- LOSO ≈ 56,62 процесс-ГП-ч;
- проверка дозы ≈ 1,5 ГП-ч + зонд.

```python
import csv, collections, json, numpy as np
# U39: группы VSSigns Logos на глоссах Slovo
g = collections.defaultdict(set)
for r in csv.DictReader(open('class_ids.tsv'), delimiter='\t'):
    g[r['VSSign_group_ID']].add(r['lemma'].strip().lower())
lem2g = {l: k for k, v in g.items() for l in v}
sl = {r['text'].strip().lower() for r in csv.DictReader(open('datasets/slovo/slovo/annotations.csv'), delimiter='\t')} - {'no_event'}
grp = collections.defaultdict(list)
for x in sl:
    if x in lem2g: grp[lem2g[x]].append(x)
multi = [v for v in grp.values() if len(v) > 1]
print(len(sl), sum(map(len, grp.values())), len(grp), len(multi), sum(map(len, multi)))  # 998 987 808 120 299
# U38: покрытие ALL-UZ парами Slovo / Bukva по gloss_map (ru→uz)
z = np.load('osnovnaya_model/cache/M13/alluz.npz', allow_pickle=True); c = json.loads(z['clips'].item())
cls = collections.Counter(x['gloss'] for x in c)
m = json.load(open('datasets/gloss_map.json'))['map']
can = {v['canonical'] for k, v in m.items() if 'ru→uz' in v['method'] and k.strip().lower() in sl}
bk = {r['text'].strip().lower() for r in csv.DictReader(open('datasets/bukva/bukva/annotations.csv'), delimiter='\t')}
w = [k for k in cls if k in can]; b = [k for k in cls if k.startswith('harf:') and k[5:] in bk]
print(len(w), sum(cls[k] for k in w), len(b), sum(cls[k] for k in b))  # 190 860 29 62
```
