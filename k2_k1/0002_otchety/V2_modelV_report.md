## 0. Кэш ASL (`osnovnaya_model/cache/asl_signs.npz`; `scripts/build_asl_cache.py` + `tests/test_asl_cache.py`)

**Сводка:** 94 477 записей (все строки `train.csv`, без потерь: `no_pose` 0), **21 исполнитель** (`participant_id` → `asl<id>`),
**250 классов** (`sign`), 3 583 987 кадров; длина записи — медиана 22 кадра (5–95 %: 6–135; Slovo — 47). Доля кадров:
поза 100 %, лицо 99,3 %, левая кисть 30,4 %, правая 30,9 %, **хотя бы одна кисть — 60,9 %** (Slovo: каждая кисть ≈ 72–74 %).
Разбиение предобучения: train 89 724 (20 исп.), val 4 753 (1 исп.), классов val вне train — 0
(`splits/asl_signs_pretrain_all.json`, вне git; в `splits/sizes.json` — только счётчики).

**Проверки и допущения (выборка 4 000 записей, все 21 исполнитель, затравка 0; сравнение с кэшами Slovo/Bukva):**
1. **Точки.** Порядок 85 точек — `mpk.data.MPK_POINTS`, раскладка 543 → Э0 553 явная (по `type`/`landmark_index`, тест).
   Старый Holistic: сетка лица 468 без радужки → **центры радужек 468/473 = средние углов век 33/133 и 362/263**
   (оговорка SPEC_MPK §10.6 п. 17). Соответствие проверено на Slovo: |468 − ср(33,133)| = 0,0025, до другого глаза — 0,088;
   |473 − ср(362,263)| = 0,0026.
2. **Соглашение рук совпадает с нашим Holistic Landmarker — перестановки нет** (`SWAP_HANDS = False`):
   запястье `left_hand` ближе к точке позы 15 (левое запястье) в 99,8 % кадров (Slovo 97,4 %, Bukva 98,7 %);
   `left_hand` правее носа на изображении в 99,4 % кадров (Slovo 93,5 %), `right_hand` — в 0,4 % (Slovo 7,6 %); плечо 11
   правее 12 — 100 % (как у нас). Т. е. `left_hand` = анатомически левая кисть на незеркальном (или так размеченном) кадре.
   **Зеркальность не устанавливается по точкам**: у 9 из 21 исполнителя ведущая (единственная видимая) кисть — `left_hand`
   (у 12 — `right_hand`; 43 % «левшей» неправдоподобно для населения) — часть записей, вероятно, снята фронтальной камерой
   с зеркалом или это левши. Отражение не делаем: A-доминант отклонён в M7 (§10.9); это риск переноса.
3. **Диапазон координат:** доли кадра, как у нас; поза выходит за кадр (y до ≈ 1,5 — бёдра; x от −0,14), кисти в [0,28; 0,97].
4. **aspect (H/W) неизвестен → 1,43 для всех записей.** Оценка по геометрии лица: отношение «лоб–подбородок (151–152) /
   межглазное (33–263)» в изотропных координатах на Slovo/Bukva = 1,80 (медиана); оценщик aspect, при котором это отношение
   = 1,80, проверен на Slovo/Bukva с известным aspect: 0,562 → 0,55; 1,0 → 1,01; 1,778 → 1,74/1,80 (2,336 → 2,53). На ASL по
   исполнителям 1,31–1,61, **медиана 1,43** (портрет; между 4:3 = 1,33 и 3:2 = 1,5). Допущение: один aspect на все записи,
   ошибка у отдельных исполнителей до ±0,15 (≈ ±10 % по вертикали); аугментации масштаба/поворота частично покрывают.
5. **vis позы нет** в `asl-signs` → для 6 точек позы — средняя vis той же точки на Slovo в кадре / вне кадра
   (11, 12: 1,0/0,99; 13, 14: 0,97–0,95/0,89–0,87; 23, 24: 0,94–0,93/0,29–0,28).
6. **fps неизвестен**; кадры — строки по возрастанию `frame` без заполнения пропусков номеров. Записи короче Slovo
   (22 против 47 кадров) — окно T = 32 с темпом 0,5–2 растягивает их; рассогласование темпа — риск.
7. Экстрактор другой: в кэше `e0_model_sha256 = asl-signs:kaggle-legacy-holistic-543`; `mpk.train` принимает его только при
   явном `data.sets.asl_signs.extractor` (иначе assert, как раньше).
8. Пробный прогон (28.10, 17:27, ГП 40 с, 30 шагов): три головы, доли батча Slovo 23 / Bukva 4 / ASL 101; дообучение
   `uzsl` от этой точки — 20 шагов, загружены 208 тензоров кодировщика, головы `uzsl` новые. Выходы — `runs/modelV/smoke/`.

## 1. Предрегистрация (зафиксировано и закоммичено ДО обучения, 28.10.2026)

**1. Предобучение.** Рецепт A1 без изменений: конфиг `osnovnaya_model/configs/M8/m83_pretrain_sb_a1.yaml` (A0 + EMA,
D 192, N 3, батч 128, lr 1e-3, `compile`, `select: best_val`), к его наборам `slovo`, `bukva` добавлен набор `asl_signs`
со своей временной головой (250 классов; батч делится между наборами пропорционально числу записей train — как в
M6/M8). Разбиение ASL — то же правило §5.0 п. 2, что `*_pretrain_all`: все записи в train, round(0,05 · 21) = 1
исполнитель (4 753 записи) — val для выбора контрольной точки (затравка разбиения 0); `boundary_inward_only: true`
(запись = вырезанный жест). Все записи всех трёх наборов, затравки **0, 1, 2**.
**Бюджет — правило m83 (M6): шагов = ⌈100 · Σ N_train / 128⌉** (100 эпох по train). m83: ⌈100 · (19 979 + 3 581) / 128⌉ =
18 407 (сверено assert'ом в коде); **В: ⌈100 · (19 979 + 3 581 + 89 724) / 128⌉ = 88 504 шага**, проверка каждые
⌈шагов/20⌉. Код: `uzsign_ai_v2/scripts/loso.py pretrainV` → `runs/modelV/pretrain/seed<k>/best.pt`.

**2. Дообучение — точно протокол шага 1.** 682 класса, `cache/uzsl.npz`, `splits/uzsl_loso.json` (11 фолдов: 10
исполнителей + «other»), одна узбекская голова `uzsl`, рецепт A1 ft пилота M8.3, **209,45 эпохи** →
⌈209,45 · n_train / 128⌉ шагов, заморозка 20 %, послойная разморозка каждые 1/15, lr основы ×0,1, EMA, `merge_val`,
**веса последнего шага**; затравка дообучения = затравке предобучения → 33 прогона (`loso.py runV` →
`runs/modelV/loso/<фолд>/seed<k>`). Отличие от шага 1 — только путь `init_from`.

**3. Метрики** — как шаг 1 §1 п. 5 (top-1/top-5 macro по 10 исполнителям, 95 % ДИ бутстрепом по исполнителям, micro,
SD по затравкам, слова/дактиль, частые ошибки) **+ парная разность В − шаг 1** по исполнителям (точность на общих
записях фолда, среднее по 3 затравкам; 95 % ДИ — бутстреп по исполнителям, 10 000, затравка 0; n_positive из n) — всего,
слова (исполнители с ≥ 10 записями слов), дактиль (≥ 10 записей дактиля). Справочно — В − А (шаг 1b), если А готова.
Сводка: `scripts/summarize.py modelV` → `reports/V2_modelV_results.json`.

**4. Итоговая модель В** — тот же рецепт на всех 3 418 записях, предобучение seed0, последний шаг (`loso.py finalV` →

## 3. Выводы
1. ASL в предобучении **не улучшил** общую точность на УзЖЯ (разница не установлена).
2. **Слова — слабый выигрыш** (top-5 +2,4, значимо): разнообразие словарного предобучения немного помогает узнавать слова.
3. **Дактиль — проигрыш** (−10 п.п.): в `asl-signs` нет дактиля, ASL занимает ≈ 79 % батча и, вероятно, вытесняет дактильную часть (Bukva) из предобучения. Проверяемая гипотеза (не проверена): балансировка источников в батче (напр. ASL ≤ доли Slovo) или раздельные модели для слов и дактиля.
4. Оговорки: aspect ASL оценён (1,43), часть записей ASL, возможно, зеркальна (9 из 21 исполнителя с ведущей `left_hand`), fps неизвестен; ASL — другой экстрактор (старый Holistic).
5. Для итоговой системы — пока модель шага 1. Решение по ASL (балансировка / отказ) — на встрече.
