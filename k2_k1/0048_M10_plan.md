# M10 — план серии «надёжное распознавание и адаптация к пользователю» (черновик, 03.11.2026)

Серия M10 — кандидаты M8-1…M8-6 из дельта-исследования консультанта_1 (25.10.2026, §4.3–4.5, §10). Порядок — по ценности для защиты: **M10-0 (имитация Н4) → M10-1 → M10-4 → M10-3 → M10-2 → M10-5 → M10-6**. Позиция автора (03.11): глава 4 — академическая. Её ядро — «не знаю» с гарантией (M10-1, M10-2) и адаптация к пользователю (M10-4). К ним — короткий раздел «прототип и апробация». Методика корпуса идёт в гл. 2 (пункт К), «точность / стоимость» — в гл. 3. **До согласования с консультантом_1 и подписи автора ничего не запускать.** Перед каждым опытом в git коммитится предрегистрация с правилами вывода.

## 1. Опыты

### M10-0. Имитация Н4 на Slovo/Bukva (предложение к1, 0023) — первый шаг, без обучения

| поле | содержание |
|---|---|
| Гипотеза | Н4: регистрация нового пользователя по k размеченным жестам без градиентов повышает top-1 на его остальных записях и не ухудшает бо́льшую часть исполнителей. |
| Схема | Тестовый исполнитель фолда (модель его не видела). Выбираются k записей регистрации, R = 20 выборок на исполнителя. Тест — остальные его записи. В опыт входят исполнители с ≥ k + 5 записями: при k = 10 это Bukva — 120 из 155, Slovo — 86 из 188. |
| **Важное ограничение данных** | В Bukva каждый исполнитель показывает каждую букву **один раз**: 0 повторов пар «исполнитель–класс» из 3 757. В Slovo повторов 404 из 6 405 пар. Поэтому на Slovo/Bukva проверяется только **адаптация, не зависящая от класса** (перенос на незарегистрированные классы). Сценарий «тот же жест повторно» проверяется только на корпусе УзЖЯ: там 907 пар с повторами (M10-4). |
| Методы (соперники из дельта-исследования) | (0) без адаптации; (1) перецентрирование вложений пользователя: сдвиг среднего, порог 1/√n [39]; (2) прототипы NCM, обновлённые примерами пользователя [7; 22; SIGHT 34]; (3) ридж-голова в замкнутой форме на замороженном A1 (обучение + примеры пользователя с весом w) [7]; (4) справочно — дообучение головы градиентом (ЦП). Пары для вывода: **один и тот же тип головы с регистрацией и без неё** — так эффект головы отделяется от эффекта адаптации. |
| Фиксируется до опыта | k ∈ {1, 3, 5, 10}; w ∈ {1, 5}; ридж λ — по валидации фолда (исполнители валидации тоже имитируют регистрацию), не по тесту. Главная точка — k = 10. |
| Метрики | Прирост top-1 по исполнителю. **Доля ухудшившихся исполнителей** (Δ < 0 при усреднении по R). Худший исполнитель. Кривая «прирост от k». Проба узнавания исполнителя по вложениям до и после (Н2, справочно). |
| Правило | ★ Метод принимается, если нижняя граница 99 % ДИ прироста при k = 10 больше 0 **и** доля ухудшившихся ≤ 10 %. Порог 10 % взят из дельта-исследования, его нужно согласовать. |
| Прогоны / ГП | Обучения нет. Кэш вывода 30 + 10 моделей — **≈ 0,3–0,5 ч ГП** (или несколько часов ЦП). Адаптация и оценка — на ЦП, минуты. |
| Риски | Записи одного исполнителя обычно сняты в одном сеансе, поэтому прирост может быть завышен (адаптация к сеансу, а не к человеку) — отметить, распределение по сеансам неизвестно [8]. Нормировка МПК уже убирает масштаб, так что прирост от (1) может быть ≈ 0. Головы A1 обучены с CE и LayerNorm, поэтому прототипы на вложениях надо проверить на валидации. |

### M10-1 (M8-1). Конформное «не знаю» для нового исполнителя: HCP против Мондриана и объединённого split-КП

| поле | содержание |
|---|---|
| Гипотеза | Н3: иерархическая калибровка HCP [26] (вес исполнителя 1/(K+1)) держит покрытие ≥ 1 − α на **новых** исполнителях. Объединённый split-КП (записи считаются перестановочными) и «Мондриан для нового» — нет. |
| Схема (Slovo/Bukva) | Внутри фолда тестовые исполнители случайно делятся на калибровочные (K) и тестовые; ни тех, ни других модель не видела. R = 1 000 повторов. K ∈ {5, 10, 18} (18 — половина фолда, запас 2/(K+1) ≈ 0,105). Справочно: K ≈ 30 при добавлении исполнителей валидации — они участвовали в выборе контрольной точки, это оговаривается. |
| Соперники | (а) **HCP** [26]; (б) объединённый split-КП; (в) Мондриан по исполнителям. Для нового исполнителя он не определён, наша операционализация — средний порог по группам (согласовать с к1); (г) порог по max-softmax без гарантии (как RSC-GestureNet [31]) при той же доле «не знаю». |
| Балл | LAC (1 − p_y) — главный. APS — справочно. Softmax без перекалибровки температуры (фиксируется). |
| Фиксируется | α ∈ {0,1; 0,2}; K как выше; «не знаю» = множество размером > 1 (ответ выдаётся, только если множество из одного класса); top-k-режим демо: множество обрезается до 5. |
| Метрики | Покрытие на новом исполнителе: среднее по исполнителям, распределение, худший исполнитель, **доля исполнителей с покрытием < 1 − α − 0,1**. Условное покрытие по исполнителям и по числу их записей. Средний размер множества. Доля «не знаю». Точность на принятых (выборочная). |
| Правило | ★ HCP «держит покрытие», если нижняя граница 99 % ДИ (бутстреп по тестовым исполнителям) среднего покрытия ≥ 1 − α − 0,01. Тогда п. 3.3 строится на HCP. ★ Парная разность доли исполнителей с недопокрытием «split − HCP» > 0 → вывод «split не держит» (довод [28]). |
| УзЖЯ | Перекрёстная калибровка по готовым LOSO-моделям: балл каждой записи берётся от модели фолда, не видевшей её исполнителя. Тест — исполнитель i, калибровка — остальные 9 (K = 9, запас 0,2, α = 0,1 на границе достижимости). Гарантия здесь **приближённая** (баллы от разных моделей). Точная (вложенный LOSO) потребует обучения — см. риски. N01: калибровка на 10 исполнителях, тест итоговой моделью; это проверка «новый источник». |
| Открытое множество (M10-1b) | N01 даёт естественную смесь: 93 записи в словаре и 98 вне его. Сравнение: символ «вне словаря» по p-значениям Гуда–Тьюринга [25] против LTT [дельта, 4.4] и против порога max-softmax. Отчёт отдельно по известным, неизвестным и смеси [37]. На Slovo — опционально: модели без 20 % классов, 1 × 5 (≈ 0,3 ч ГП). |
| Прогоны / ГП | **Без обучения**: кэш M10-0, плюс ≈ 0,1 ч на LOSO и N01. Калибровка — ЦП. Опция 1b на Slovo — ≈ 0,3 ч, Bukva — ≈ 0,1 ч. |
| Риски | На Slovo много исполнителей с 1–3 записями: покрытие отдельного исполнителя дискретно, поэтому главная метрика — среднее, худший — справочно. Исполнитель с 400 записями даёт перекос в объединённом split — это часть доказательства, не ошибка. Калибровку для телефона потом повторить на int8 (Э6/Э7 [29]) — вне M10. |

### M10-4 (M8-4). Регистрация пользователя на корпусе УзЖЯ (Н4, узбекская часть)

| поле | содержание |
|---|---|
| Гипотеза | ~10 размеченных жестов пользователя дают прирост top-1 без ухудшения исполнителей. Для зарегистрированных классов прирост больше. |
| Схема | Готовые LOSO-модели (33). Для отложенного исполнителя — k записей регистрации, R = 20; тест — остальные. Отдельно отчитываются две группы теста: записи **зарегистрированных** классов (повторы есть) и прочих классов. Распределение регистрации по урокам/сеансам фиксируется; где можно — регистрация из другого урока, чем тест [8]. N01: только класс-независимые методы (по 1 записи на класс). |
| Методы, k, w | Как M10-0: те же 4 метода, k ∈ {1, 3, 5, 10}, параметры **переносятся из M10-0 без подбора на УзЖЯ**. |
| Метрики / правило | Прирост, доля ухудшившихся, худший. ★ Нижняя граница 99 % ДИ (бутстреп по 10 исполнителям) > 0 и доля ухудшившихся ≤ 10 %. При 10 исполнителях ДИ широкий, так что «не установлено» — вероятный исход. Вывод делается по Slovo/Bukva, УзЖЯ — подтверждение. |
| Прогоны / ГП | **Без обучения**, вывод ≈ 0,1 ч ГП. Опция для архитектуры — SL-GCN на УзЖЯ — требует его LOSO (см. разд. 3). |
| Риски | Метки корпуса не проверены. Ведущий канала = исполнитель, поэтому «новый человек» = «новый канал» (сдвиг смешанный). Повторы в одном уроке завышают прирост. |

### M10-3 (M8-3). Перенос длин костей (идея автора, Н2) — нужно обучение

| поле | содержание |
|---|---|
| Гипотеза | При N ≤ 10 реальных исполнителях синтез исполнителей переносом длин костей (прямая кинематика 2D, включая фаланги) помогает **как стадия предобучения** и не помогает или вредит в смеси [13; 17; 18]. |
| Данные | Bukva, протокол П. Моделируется N ∈ {3, 5, 10, 30} обучающих исполнителей (фиксированные подвыборки). Длины костей берутся (а) у других обучающих исполнителей, (б) из распределения Slovo, **никогда — у тестового**. Пилот — справочно. |
| Соперники / контроли | Только реальные данные. Синтез в смеси. Синтез → дообучение. Случайное масштабирование той же амплитуды (EnsAug-типа [23]). Нормировка длин вместо синтеза. «Оракул» — длины тестового исполнителя. Прототипы по 10 примерам без синтеза (из M10-0, без обучения). |
| Метрики / правило | top-1 по исполнителям, худший исполнитель, доля ухудшившихся, проба узнавания исполнителя. ★ Идея принимается, если при N ≤ 10 нижняя граница 99 % ДИ парной разности к **лучшему контролю** > 0 (дельта, 4.3). |
| Прогоны / ГП | 4 N × 6 обучаемых условий × 5 фолдов × 3 затравки = **360 прогонов Bukva** (≈ 35 с ГП на прогон при 3 параллельно) ≈ **4–6 ч ГП** вместе с предобучениями на синтетике. Плюс пилот ≈ 1 ч. Код прямой кинематики и ограничения контактов — на ЦП, до запуска. |
| Риски | Ракурсное сокращение в 2D: длину брать медианой по фронтальным кадрам. Сдвигаются точки контакта «кисть–лицо», а место жеста различительно: нужна локальная обратная кинематика. Нормировка МПК может дать тот же эффект, поэтому нужен контроль «нормировка длин». Стиль и темп не переносятся [14]. |

### M10-2 (M8-2). GHCP: «не знаю» с учётом регистрации (связка Н3 + Н4)

| поле | содержание |
|---|---|
| Гипотеза | GHCP [27] с o примерами нового пользователя сужает множества по сравнению с HCP и сохраняет покрытие. Запас убывает с ростом o. |

## 3. Для статьи 3 и главы 4; SL-GCN + токены частей

| куда | что из M10 |
|---|---|
