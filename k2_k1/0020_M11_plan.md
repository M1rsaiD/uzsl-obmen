## Часть А. Готовые модели авторов Slovo против МПК на официальном разбиении Slovo

### А.1. Что сравниваем
Опубликованные модели авторов (github.com/hukenovs/slovo; числа из README авторов, «accuracy» на официальном тесте):

| модель | кадры / шаг | опубликовано | размер | на ПК |
|---|---|---|---|---|
| MViTv2-S | 16 / 4 | 58,35 | 140,5 МБ | нет — скачать |
| **MViTv2-S** | **32 / 2** | **64,09** | 140,8 МБ | **есть** (`mvit32-2.onnx`) |
| MViTv2-S | 48 / 2 | 62,18 | 141,1 МБ | есть (`mvit48-2.pt`) |
| Swin-large | 16/3, 32/2, 48/1 | 48,04 / 54,84 / 55,66 | 821,7 МБ | нет — скачать (3 × 822 МБ) |
| ResNet-i3d | 16/3, 32/2, 48/1 | 32,86 / 38,38 / 43,91 | 146,4 МБ | 32/2 есть (`resnet32-2.pt`) |

Наши (только Slovo, официальное разбиение, без Bukva/пилота): **A1** (3 затравки — готовы, M9.3), **A2** (без графа — 3 затравки, новые), **A1-большая** (3 затравки, новые), **ансамбль 3 затравок A1** (без обучения).

### А.2. Протокол
1. **Тест:** полный официальный тест Slovo, 5 100 записей, 174 исполнителя (без `no_event`). У всех моделей одинаковый набор записей.
2. **Проверка воспроизведения (ворота):** сначала прогоняем `mvit32-2` по инструкции авторов (кадры, шаг, размер, нормировка — из их репозитория/конфигов). Если наш результат отличается от опубликованных 64,09 более чем на 1,0 п. п. — **стоп**, разбираем препроцессинг, остальные модели не запускаем. Так же — для каждой модели: расхождение с опубликованным > 1,0 п. п. помечается и объясняется.
3. **Класс `no_event`:** головы авторов имеют 1 001 выход (как у нас). Ответ = argmax по всем 1 001, как у авторов; доля ответов `no_event` сообщается отдельно.
4. **Метрики:** top-1, top-5 по записям; средняя точность по классам (если авторы считают «accuracy» как mean class accuracy — уточнить по статье arXiv:2305.14527 и отчитываться обеими); 95 % ДИ бутстрепом по исполнителям (2 000 повторов, фиксированная затравка, сортировка исполнителей — как после M9.1); **парная разность A1 − модель** по исполнителям; вывод по §6 SPEC.
5. **Стоимость:** параметры, размер файла, GFLOPs, задержка на ЦП (тот же сеанс, i9-14900KF, batch 1) и на ГП; для видеомоделей — включая декодирование кадров отдельно.
6. **Оговорка (в отчёт):** официальное разбиение пересекается по исполнителям (92 из 174 тестовых есть в train) — для **обеих** сторон одинаково; на протоколе П готовые модели использовать нельзя.

### А.3. Ресурсы
Скачивание: 4 недостающих MViTv2/ResNet ≈ 0,6 ГБ + Swin-large ≈ 2,5 ГБ (по «да» автора; источник — официальный репозиторий авторов). ГП: видео-инференс 9 моделей × 5 100 записей ≈ 2–3 ч; A2 и A1-большая на официальном разбиении 6 прогонов ≈ 1 ч.

### Б.1. Факты (страница соревнования, проверено 02.11.2026)
- 1 165 команд, 20 210 отправок; закрыто 02.05.2023; **поздние отправки открыты** (кнопка «Late Submission» у аккаунта автора).

- Данные: Mediapipe 0.9.0.1, 543 точки (сетка лица 468 без радужки), 94 477 записей, 250 классов. Внешние открытые данные и предобученные модели разрешены.

### Б.3. Протокол обучения (до отправок)
1. **Внутренняя проверка — по исполнителям:** GroupKFold по 21 исполнителю (5 фолдов; фолды и затравки закоммитить до обучения). Рецепт A1 — без изменений; бюджет шагов — по правилу M8 (эпохи на запись), записать до обучения. Выбора по тесту нет; итоговые модели — на всех 94 477 записях, последний шаг.
2. **Препроцессинг — внутри графа модели** (потому что на входе сырые 543 точки с NaN): выбор 85 точек МПК (центры глаз = средние углов век 33/133 и 362/263 — как в модели В), NaN → 0 + маска частей, временная выборка до T = 32 по равномерной сетке (вместо интерполяции по уроку), aspect — константа 1,43 (оценка модели В). **Обучение — с тем же препроцессингом**, чтобы train/infer совпадали.
3. **Конвертация:** PyTorch → ONNX → TensorFlow (onnx2tf) → TFLite; проверка: на 1 000 записях валидации максимальная разность вероятностей < 1e-4 и совпадение argmax ≥ 99,9 %; точность TFLite = точности PyTorch в пределах 0,1 п. п. Проверка совместимости с runtime 2.9.1 (операции attention/GELU/LayerNorm); при несовместимости — переписать блоки в Keras (как Sohn) с переносом весов и той же проверкой.
4. **Ограничения:** размер (≤ 40 МБ) и задержка (< 100 мс/видео на ЦП, близком к Kaggle) — измерить локально до отправки.
5. **Отправка:** приватный датасет Kaggle с `.tflite` (только веса на данных соревнования — без пилота/корпуса/Slovo-кадров) + ноутбук; **кнопку отправки нажимает автор или консультант_2 по его «да» на каждую отправку**.

### Б.4. Ресурсы
ГП: CV 5 фолдов × 1 затравка (A1) ≈ 3–5 ч; итоговые модели 4 (A1) + 1 (A2) + 1 (предобучение) ≈ 3–4 ч; конвертация и проверка — полдня работы. Итого ≈ 1–1,5 суток с проверками.
