## M12-3. Синтез исполнителей переносом длин костей (бывший M10-3, без изменений по существу)
- Bukva, протокол П; моделируются N ∈ {3, 5, 10, 30} обучающих исполнителей (фиксированные подвыборки, затравка 20261103); длины костей (2D прямая кинематика, включая фаланги; медиана по фронтальным кадрам; локальная обратная кинематика для контакта «кисть–лицо») — (а) у других обучающих исполнителей, (б) из распределения Slovo, **никогда — у тестового**.
- Условия (6 обучаемых): только реальные; синтез в смеси; синтез → дообучение (стадия предобучения); случайное масштабирование той же амплитуды (EnsAug); нормировка длин вместо синтеза; «оракул» — длины тестового (справочно, верхняя граница). Без обучения — прототипы по 10 примерам (кэш M10-0).
- Модель — A1 (основная); строка на оригинальном SL-GCN — справочно, только для победителя (+≈ 2 ч).
- ★ Идея принимается, если при N ≤ 10 нижняя граница 99 % ДИ парной разности «лучшее условие с синтезом − лучший контроль» > 0. Лучший контроль выбирается **по валидации**, не по тесту.
- **ГП:** скрининг 4 N × 6 × 5 фолдов × 1 = 120 прогонов Bukva (≈ 35 с на прогон при 3 параллельных) + 20 предобучений на синтетике ≈ **1,5–2,5 ч**; победитель и лучший контроль до 3 затравок (+80 прогонов) ≈ +1 ч; пилот справочно ≈ +0,5 ч. Код прямой кинематики — на ЦП до запуска.

## M12-2. Гибрид: оригинальные блоки SL-GCN по частям → токены частей → слияние вниманием + Conformer
- Устройство: 4 части тела МПК (левая кисть 10 узлов, правая кисть 10, тело 4, лицо 3 + `rest_mlp` по всем 85 точкам, как у A1); на каждую часть — оригинальные блоки SL-GCN (`decouple_gcn_attn.TCN_GCN_unit`: развязанная ГС, STC-внимание, DropGraph) на подграфе части; выход блока по узлам части → токен части на кадр (как токены A1); слияние токенов вниманием (`fuse_q/fuse_k` A1) → Conformer (голова МПК: 3 слоя, D 192, пул вниманием, головы частей, прототипы).
- Против **оригинального SL-GCN тем же рецептом и тем же входом**: вход берётся по итогу M12-1 (если ★ B у SL-GCN — оба на Н2 6 каналов; иначе оба на их 3 каналах), чтобы разность была только в архитектуре. Против их входа (Г2-2) — справочно.
- ★ гибрид − оригинальный SL-GCN > 0 (99 %) на Slovo; Bukva — вторая главная строка. Абляция (справочно, Bukva 1 × 5): **слияние конкатенацией + линейный слой (как SignSeek)** против слияния вниманием — именно это отделяет наш вклад от SignSeek (ниже).
- **ГП:** 4 кодировщика по 10–4 узлам ≈ 1,0–1,3× стоимости одного SL-GCN на 27 узлах + Conformer → Slovo 1 × 5 ≈ 2,5–3,5 ч (2 параллельно), Bukva 1 × 5 ≈ 0,5 ч, абляция слияния ≈ 0,5 ч → скрининг **≈ 3,5–4,5 ч**; победитель до 3 затравок ≈ +6–8 ч.

### SignSeek (arXiv 2609.03695) — что уже есть и чем M12-2 отличается
Asasi, Mercanoglu Sincan, Bowden (CVSSP, Surrey), «SignSeek: Learning Transferable Representations for Sign Dictionary Retrieval», 2026. Найдена и прочитана (alphaXiv, полный текст).
| | SignSeek | M12-2 (гибрид) |
|---|---|---|
| Части | 4 артикулятора: тело, лицо, левая и правая кисть — **те же 4, что у нас** | 4 части МПК (+ `rest_mlp` по всем 85 точкам) |
| Вход | 3 канала (x, y, уверенность) на часть | Н2: 6 каналов (тело + **локальные системы частей**, маска, уверенность) — или 3, по итогу M12-1 |
| Графовый блок | адаптивная ГС (обучаемая смежность) + временная свёртка + squeeze-excitation; кисти — **один общий кодировщик** с зеркалом правой | **оригинальные блоки SL-GCN** (развязанная ГС, STC-внимание, DropGraph), отдельные кодировщики частей (общие кисти у A1 проверены в M7 — `a_obshchie_kisti`) |
| Из узлов в токен | развёртка узлов + линейный слой W_agg (весы по узлам) | токен части как у A1 (пул по узлам части) |
| Слияние частей | **конкатенация** 4 потоков → линейный слой → Conformer | **слияние вниманием** по токенам частей (`fuse_q/k`) → Conformer; вспомогательные головы частей |
| Цель обучения | контрастная (SupCon по глоссам) + маскирование ведущего артикулятора по значимости (ASGM: MAC, MAP); предобучение на 266 тыс. записей, ≈ 5 700 глосс, 5 корпусов | CE + прототипное вложение + головы частей; предобучение Slovo + Bukva (≈ 24 тыс. записей) → перенос на УзЖЯ |
| Задача | поиск по словарю жестов (открытое множество, без дообучения), перенос на ISLR и выравнивание субтитров | изолированные жесты малоресурсного языка, протокол «новый исполнитель», перенос РЖЯ → УзЖЯ |
**Вывод для статьи:** «графовые кодировщики по частям тела + Conformer» как таковые — **не новизна** (SignSeek, 2026; ссылаться обязательно). Наш вклад формулировать как: (1) проверенные оригинальные блоки SL-GCN в частях (воспроизведение Г2-2), (2) представление Н2 (M12-1 — отдельная проверка), (3) слияние вниманием по токенам частей с головами частей — с абляцией «конкатенация как SignSeek», (4) малоресурсный перенос на УзЖЯ. Если абляция покажет «внимание ≈ конкатенация», пункт (3) из вклада убрать.
