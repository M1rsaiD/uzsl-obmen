## Часть А. Готовые модели авторов Slovo против МПК (официальное разбиение)

### А.1. Модели
- **Авторы (только то, что уже на ПК, без скачивания):** MViTv2-S 32/2 (`mvit32-2.onnx`, опубликовано **64,09**) — ворота; MViTv2-S 48/2 (`mvit48-2.pt`, **62,18**); ResNet-i3d 32/2 (`resnet32-2.pt`, **38,38**).
- **Остальные модели авторов не скачиваем и не запускаем** — цитируем опубликованные числа из README github.com/hukenovs/slovo (на 02.11.2026: MViTv2-S 16/4 — 58,35; Swin-large 16/3 · 32/2 · 48/1 — 48,04 · 54,84 · 55,66; ResNet-i3d 16/3 · 48/1 — 32,86 · 43,91; в отчёте — дата и коммит README).
- **Наши (только Slovo, официальное разбиение):** A1 (3 затравки — готовы, M9.3); A2 (без графа, 3 затравки — новые); A1-большая (3 затравки — новые). **Ансамбль 3 затравок A1** — отдельной строкой с пометкой «ансамбль», сравнивается только справочно, **в правила вывода не входит**.

### А.2. Протокол
1. **Тест:** полный официальный тест Slovo — 5 100 записей, 174 исполнителя, один набор для всех моделей.
2. **Препроцессинг моделей авторов — только из их кода/конфигов, фиксируется в git до прогона** (кадры, шаг, размер, нормировка, выборка окна). **Подбор по тестовым видео запрещён** (в прежнем прогоне на 966 записях способ выборки подбирался по тесту — не повторяем; это прямо отмечается в отчёте).
3. **Ворота:** MViTv2-S 32/2 на полном тесте; расхождение с 64,09 > 1,0 п. п. → **стоп и отчёт, без подгонки**; остальные модели авторов не запускаются. Для каждой следующей модели расхождение > 1,0 п. п. помечается и объясняется.
4. **Метрика авторов:** в статье (arXiv:2305.14527) «accuracy» явно не определена (дословно: «Since each gesture corresponds to 20 video samples, we validated the models on the test set»); README — «accuracy». Поэтому считаем **обе**: top-1 по записям и среднюю по классам (+ top-5). При 20 записях на класс они близки; расхождение — в отчёт.
5. **`no_event`:** 1 001 выход, ответ — argmax по всем, как у авторов; доля ответов `no_event` — отдельно.
6. **Статистика:** 95 % ДИ бутстрепом по исполнителям (2 000 повторов, фиксированная затравка, сортировка исполнителей — как после M9.1); **парная разность A1 − модель** по исполнителям; вывод по §6 SPEC.
7. **Стоимость:** параметры, размер, GFLOPs, задержка ЦП (один сеанс, i9-14900KF, batch 1) и ГП; у видеомоделей декодирование кадров — отдельно.
8. **Оговорка:** официальное разбиение пересекается по исполнителям (авторы: «groups of subjects in these two sets intersect»; у нас посчитано 92 из 174 тестовых — 3 448 из 5 100 записей) — одинаково для обеих сторон; на протоколе П модели авторов не используются.

### А.3. Ресурсы
Без скачивания. ГП: 3 видеомодели × 5 100 записей ≈ 1–1,5 ч; A2 и A1-большая на официальном разбиении — 6 прогонов ≈ 1 ч. Итого ≈ 1 день с отчётом.

*(Не входит, по желанию автора отдельно: наши базовые линии ST-GCN / SL-GCN / трансформер E1 на официальном разбиении — 9 прогонов, ≈ 3–5 ч ГП.)*

## Часть Б. Kaggle «Google – Isolated Sign Language Recognition» (`asl-signs`), поздние отправки

### Б.1. Условия — цитаты со страницы соревнования (обращение 02.11.2026, kaggle.com/competitions/asl-signs)
- «You will create a TensorFlow Lite model trained on labeled landmark data extracted using the MediaPipe Holistic Solution.»
- «Your model must be packaged into a submission.zip file and compatible with the TensorFlow Lite Runtime v2.9.1.»
- «Your model must also perform inference with less than 100 milliseconds of latency per video on average and use less than 40 MB of storage space. Expect to see approximately 40,000 videos in the test set.»
- «The evaluation metric for this contest is simple classification accuracy.» «The private leaderboard is calculated with approximately 50% of the test data.»
- Отправка — через ноутбук Kaggle (≤ 9 ч, без интернета); «Freely & publicly available external data is allowed, including pre-trained models»; кнопка «Late Submission» активна у аккаунта автора.
- **Состав теста по исполнителям:** на странице соревнования прямой фразы «исполнители теста не из train» **нет** (карточка набора: «~100k videos … performed by 21 Deaf signers»; в train — 21 исполнитель). Утверждение «новые исполнители» в предрегистрацию **не пишем**, пока не найдём первоисточник (обсуждения организаторов / статья PopSign); иначе — формулировка «скрытый тест организаторов».
- 1 165 команд; 1-е место — Hoyeol Sohn, приватный балл **0,8929** (1D-CNN + Transformer, с нуля, 4 затравки; решение-основа `akkomron/uzslr-isolated-dynamic`).

**Абляция токенов частей на `asl-signs` (без отправок, главная строка):** в тех же 5 фолдах CV по исполнителям — A1 против «без токенов частей» (= ровно конфигурация M8.5), **3 затравки сразу** (≈ 9 ч ГП, ночью), без добавления затравок по результату. Если токены помогают и на ASL — новизна подтверждена на третьем языке и чужом экстракторе (MediaPipe 0.9.0.1).

### Б.3. Протокол
1. **CV по исполнителям:** GroupKFold, 5 фолдов по 21 исполнителю; фолды, затравки и бюджет шагов (правило M8, эпохи на запись) — в git до обучения. Итоговые модели — на всех 94 477 записях, последний шаг.
2. **Препроцессинг в графе — отклонение от рецепта A1** (записать): 85 точек МПК (центры глаз = средние углов век 33/133, 362/263 — как в модели В), NaN → 0 + маска частей, T = 32 по равномерной сетке, aspect = 1,43. **Один и тот же** препроцессинг в CV, итоговом обучении и TFLite. Влияние — один раз: фолд 1, затравка 0, рецепт A1 против препроцессинга в графе; разность — в отчёт, без выбора по ней.
3. **Конвертация:** PyTorch → ONNX → TensorFlow (onnx2tf) → TFLite; на 1 000 записях валидации: max |Δp| < 1e-4, совпадение argmax ≥ 99,9 %, точность TFLite − PyTorch в пределах 0,1 п. п.; локально — размер ≤ 40 МБ и задержка < 100 мс/видео. **Если runtime 2.9.1 не принимает операции и нужен перенос в Keras — стоп и письмо** (решение автора).
4. **Отправка:** приватный датасет Kaggle с `.tflite` (веса только на данных соревнования) + ноутбук; кнопку — автор или консультант_2 по «да» на каждую отправку.

### Б.4. Ресурсы
ГП: CV 5 фолдов ≈ 3–5 ч; абляция токенов 3 × 5 фолдов ≈ 9 ч; итоговые 4 × A1 + A2 + Б-4 ≈ 3–4 ч; сравнение препроцессинга — 1 прогон; конвертация и проверки — полдня работы. Итого ≈ 2–3 дня.
