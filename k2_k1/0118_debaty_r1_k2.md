## 4. Развилки — позиция с выводом

### 4.1. U13: масштаб s

**Обозначения:** f — признак после GAP (d = 384), w_c — вес класса, c_j = cos(f, w_j), C = 3 531, ε = 0,1.

1. **На выводе s не влияет на top-1.** Для любого s > 0: argmax_c s·c_c = argmax_c c_c. Значит, s действует только через обучение.
2. **Оптимум при сглаживании.** Цель: t_y = 1 − ε + ε/C, t_j = ε/C. Минимум CE достигается при p = t. Так как p_y / p_j = exp(s(c_y − c_j)), получаем s(c_y − c_j) = ln(1 + C(1 − ε)/ε) = **ln(1 + 9C) = 10,37**. Минимум конечен — здесь к1 и к3 (0100, 0013) правы.
3. **Late dropout.** f_d = m ⊙ f / q, m_i ~ Bernoulli(q), q = 0,2 (`sohn.py`, стр. 556).
   - E‖f_d‖² = ‖f‖² / q; ожидание f_d · w равно f · w.
   - Если энергия распределена по 384 координатам: cos(f_d, w) ≈ √q · cos(f, w) = 0,447 · cos(f, w).
   - Значит, на 95 % шагов нужно s ≥ 10,37 / 0,447 = **23,2** даже при c_y = 1 и c_j = 0.
   - При s = 16: max p_y = e^{7,155} / (e^{7,155} + 3 530) = 1 280 / 4 810 = **0,27**.
4. **Обучаемый s в порте** (К-4): за всё дообучение s остаётся в [13,31; 18,65]. До 23 он дойти не может. «Обучаемый с 16» здесь ≈ «фиксированный 16 ± 2,7». Диагностика «s < 10» сработать не может.

**Позиция: фиксированный s, значение — из формул п. 2–3 до прогона.**
- s = ln(1 + 9C) / ρ̂, где ρ̂ = среднее cos(f_d, μ_y) / cos(f, μ_y).
- ρ̂ мерить на ЦП: обучающие записи базы-контроля, μ_y — средний признак класса, 10 масок dropout 0,8.
- Ожидаю ρ̂ ≈ 0,45, то есть s ≈ 23.
- Одно значение, в предрегистрацию; по V_k не подбирать.
- Если авторы предпочитают обучаемый s — только через log s. Иначе в этом оптимизаторе он фактически фиксирован.

**Чего вывод не утверждает.** Что достижимость цели сглаживания полезна для top-1, не доказано. Выбор «≈ 23, а не 16» опирается на единственный выведенный критерий, и предложил его к3. Эффект U13 измерит плечо.

### 4.2. U23: когда

1. **Монотонность.** Пусть φ — отображение объединения. Для тех же предсказаний ŷ = y ⇒ φ(ŷ) = φ(y), обратное неверно. Поэтому точность на новых метках не ниже, чем на старых, и прирост U23 частично получается по определению. Сравнения внутри этапа должны идти на одном наборе меток: «до этапа» или «после», но не посередине. Этим выводом довод к1 (0098, В5) проверен.
2. **Цена при любом времени одинакова.**
   - Нужен один перепрогон базы S_k на новых метках: Sohn · Sohn — 121 500 шагов × 512 = 62,2 млн примеров, 56,62 ГП-ч процессов (`U33_tables.md`).
   - Нужна база-контроль V_k на тех метках, на которых идёт отбор.
   - Поэтому «после» ГП не экономит.
3. **Риск «после» измерим без точности.** (а) + (б) — 26 классов и 49 записей из 7 815, то есть **0,63 %** (`runs/UZSOHN_cpu/u23.json`, поле `rows`). При таком масштабе решения этапа 1 переносятся на новые метки с малым риском. Даже для U13, где важно число классов, затронуто 24 класса из 3 531 (0,7 %).
4. **Список автора не готов** (0100, 0013). «До этапа» означает ждать.

**Позиция: после этапа 1, до U20** — по пп. 2–4, а не из согласия. Условия:
