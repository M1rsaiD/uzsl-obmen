## U19. Mixup, в том числе Manifold Mixup

1. **Механизм.** На случайном слое k из заданного набора (вход или выход блока Conv1D / трансформера) скрытые представления двух примеров смешиваются: h = λ·h_i + (1−λ)·h_j, λ ~ Beta(α, α). Цель смешивается так же: y = λ·y_i + (1−λ)·y_j. По [6th] — перед одним из слоёв трансформера, с вероятностью, которая растёт по ходу обучения как 0,5·эпоха/(0,9·N). **Поправка к моему письму 0008:** там я написал «только в первой половине обучения» — это неверно. В README «только в первой половине» относится к двум другим аугментациям: «нет кисти → взять другую» и Face CutMix (см. U07).
2. **Какую ошибку устраняет.** Переобучение на классах с малым числом записей. По Д у **67 % теста** в классе ≤ 4 обучающих записей. Top-1 Sohn: корзина «1 запись» — 5,9 %, «2–4» — 23,3 %, «≥ 5» — 43,7 %. Цепочка: при 1–4 записях граница класса проходит по самим примерам → неуверенность на интерполяциях наказывает такие границы → граница сглаживается → лучше обобщение на нового исполнителя.
3. **Доказательства.**
   - [Verma19], полный текст, с. 8: PreActResNet50, CIFAR-10, 600 эпох, тестовая ошибка — без регуляризации **4,96 ± 0,19 %**, Mixup **4,25 ± 0,11**, Manifold Mixup **3,77 ± 0,18** (5 повторов). Изображения, не позы, не мало примеров на класс, не по исполнителям.
   - [6th], README: Manifold Mixup — в списке того, что сработало в решении 6-го места GISLR (позы MediaPipe, 250 классов). Отдельного числа в README нет.
   - [Kvan24], полный текст, табл. 3: на SlovoExt (MViTv2-S, RGB) снятие CutMix + MixUp −1,89 п., снятие всех аугментаций изображения −4,06 п. RGB-видео, не точки.
4. **Где выигрыш.** Ожидаемо — корзины «1» и «2–4». Порядок величины перенести нельзя: условия источников далеки от наших (изображения, RGB, или README без числа). **Оценки нет.**
5. **Угрозы.** При 1 записи на класс смешивание двух редких классов создаёт цель, которой нет ни у одного реального примера. Возможен вред на корзине «1». Сочетание с сильным сглаживанием меток (U20) удваивает регуляризацию, поэтому подбирать их вместе. В решениях Kaggle был один исполнитель на запись и много записей на класс, а у нас LOSO.
6. **Минимальная проверка.** Плечо «Sohn + Manifold Mixup» с параметрами [6th] (α — по V_k), LOSO по 0087, отчёт по корзинам 1 / 2–4 / ≥ 5. Цена — одна серия.
7. **Взаимодействия.** U17 (подмена части тела) и U32 (×10) — тоже регуляризация через данные. Проверять по одной, иначе эффекты не разделить. U13 (прототипы) с mixup не конфликтует, но цель-смесь для косинусной головы нужно определить явно.

## U07. Кадры без кисти; max по двум кистям; «нет кисти → взять другую»

1. **Механизм.** Три независимых правки входа по [6th]. (а) Кадры, где не найдено ни одной кисти, выбрасываются до прореживания к max_len. (б) Признак двух кистей агрегируется максимумом, а не суммой или конкатенацией. (в) Аугментация: если одна кисть пропала, на её место с p = 0,25 подставляется другая. У [6th] — только в первой половине обучения: по README, это улучшало сходимость.
2. **Какую ошибку устраняет.** (а) В клипах YouTube в начале и в конце руки опущены. При фиксированном max_len эти кадры отнимают временное разрешение у самого жеста. (б), (в) — одноручные жесты и пропуски кисти.
3. **Доказательства.** [6th], README: все три — в описании решения 6-го места GISLR, без отдельных чисел. **Против (б), (в):** по Д связи пропусков кисти со снижением точности **не найдено**. Значит, у Sohn пропуски кисти — не главная ошибка.
4. **Где выигрыш.** (а) — записи YouTube: 25,4 % top-1 у Sohn против 36,4 % на пилоте, Д. Но разница может быть и от ведущих. По (б), (в) **оценки нет**, а Д говорит, что эффект, скорее всего, мал.
5. **Угрозы.** (а) Для жестов, в которых кисть выходит из кадра или прячется за телом, выброс кадров ломает движение. (в) Подстановка правой кисти вместо левой меняет смысл двуручных асимметричных жестов.
6. **Минимальная проверка.** (а) — одно плечо LOSO, по 0087. До этого бесплатно: доля кадров без кисти по контролю Э0 в записях YouTube и пилота и связь с ошибкой Sohn по источнику. (б), (в) — только если (а) даст эффект.
7. **Взаимодействия.** U06 (ведущая рука, отражение) перекрывается с (в), поэтому делать что-то одно. U11 (attention pooling) отчасти решает ту же задачу, что и (а).

## U24 (моя часть). OUSM — исключение записей с наибольшей потерей

1. **Механизм.** В каждом пакете из N записей k записей с наибольшей потерей не дают градиента. У [6th] k = 3 при пакете 32; у [Xue19] — доля пакета.
2. **Какую ошибку устраняет.** Шумные метки: записи с неверной меткой чаще всего имеют большую потерю.
3. **Доказательства.** [Xue19], полный текст, разд. 2.1 и табл. 1: ResNet-101, классификация кожных поражений, симметричный шум меток. Точность без OUSM → с OUSM: шум 5 % — **82,6 → 82,5**; 10 % — **79,1 → 81,2**; 20 % — **75,2 → 77,6**; 40 % — **65,3 → 73,6**. Выигрыш есть только при шуме ≥ 10 %, при 5 % его нет. [6th]: OUSM с k = 3 — в решении, без отдельного числа.
4. **Где выигрыш.** На ядре корпуса шум меток мал: С1 — точность меток **98,2 % [94,6; 100]**, то есть шум ≈ 2 %. По [Xue19] при таком шуме выигрыша не ждём. Выигрыш возможен только на шумных источниках расширенного корпуса (C12, N04). Их шум я не проверял, оценка «≈ 70 %» — из письма к1.
5. **Угрозы — главная.** У нас тысячи классов с 1–2 записями. Запись редкого класса почти всегда даёт большую потерю потому, что класс трудный, а не потому, что метка шумная. OUSM будет систематически выбрасывать **единственные примеры редких классов**, то есть бить ровно по корзине «1» (22,8 % теста). [Xue19] — 2 класса, [6th] — 250 классов и много записей на класс, нашего режима нет ни там, ни там. **Без поправки идею не запускать.**
6. **Минимальная проверка (с поправкой).** OUSM только для записей классов с ≥ 5 обучающими записями или только для записей шумных источников. Отчёт по корзинам и по источникам, LOSO по 0087. Цена — одна строка кода и одна серия.
7. **Взаимодействия.** U22 (поправка на частоту) и U13 (прототипы) работают на редкие классы, а OUSM без поправки — против них. Вес по надёжности источника (вариант к1 в U24) безопаснее и делается первым.

## U29. Дистилляция ансамбля, Mean Teacher

1. **Механизм.** (а) Дистилляция: ансамбль из 3 затравок Sohn — учитель. Одна модель-ученик учится на его мягких предсказаниях с температурой T плюс на истинных метках. На выводе работает одна модель. (б) Mean Teacher: учитель — EMA весов ученика, потеря согласованности между их предсказаниями. Её можно считать и на **неразмеченных** клипах.
2. **Какую ошибку устраняет.** (а) Не ошибку распознавания, а цену ансамбля на телефоне. По Д ансамбль Sohn × 3 − одна Sohn = **+1,05 [+0,07; +2,05]** (99 %), то есть ансамбль полезен, но втрое дороже. (б) Мало размеченных записей. При построении корпуса из 11 153 автоматических сегментов меток не получили около 5 тысяч (С1, разд. 3.3). Это неразмеченные клипы того же домена.
3. **Доказательства.**
   - [Hint15], полный текст, табл. 1: распознавание речи. Одна модель — точность по кадрам **58,9 %**, ансамбль из 10 — **61,1 %**, дистиллированная одна модель — **60,8 %**. WER: 10,9 / 10,7 / 10,7 %. Дистилляция сохраняет почти весь выигрыш ансамбля.
   - [Tarv17], полный текст: Mean Teacher + ResNet, CIFAR-10 с 4 000 метками — ошибка **10,55 % → 6,28 %**. В табл. 2 сверточная сеть: **12,31 ± 0,28** без учителя. SVHN с 250 метками — 4,35 %.
   - [6th], README: Mean Teacher + дистилляция в решении 6-го места GISLR, на выводе дистиллированная модель.
4. **Где выигрыш.** (а) Ожидаемо — сохранить бо́льшую часть из +1,05 п. ансамбля при цене одной модели. Это порядок из [Hint15], но условия другие: речь и 10 моделей. (б) Корзины «1» и «2–4», если неразмеченные сегменты содержат жесты этих классов. **Оценки нет.**
5. **Угрозы.** (а) Ансамбль из 3 затравок — слабый учитель, его выигрыш на нижней границе ДИ около 0,07 п. Дистилляция может не дать ничего измеримого. (б) Неразмеченные сегменты — это как раз **отбракованные** сегменты: шум, два жеста в одном, руки вне кадра. Согласованность на мусоре может вредить. Утечка: неразмеченные клипы тестового исполнителя в обучение не брать. Иначе это трансдуктивная схема (см. U31).
6. **Минимальная проверка.** (а) — после того как ансамбль UzSohn зафиксирован: ученик против одной модели, LOSO по 0087. (б) — только на неразмеченных клипах **обучающих** исполнителей фолда, отдельным плечом. Цена — ×3 на обучение.
7. **Взаимодействия.** (а) делается в самом конце, после выбора архитектуры. (б) пересекается с U26 (самообучение на неразмеченных точках): брать одно из двух. U30 (EMA) — уже часть Mean Teacher.

## U30. Суп моделей, усреднение весов (EMA, SWA)

1. **Механизм.** (а) EMA весов во время обучения (как в МПК-A1) или SWA — среднее весов последних K эпох при постоянном или цикличном LR. (б) Суп: среднее весов нескольких дообучений **от одних и тех же предобученных весов** с разными затравками.
2. **Какую ошибку устраняет.** Шум последней точки обучения. В LOSO выбора контрольной точки нет: оценивается последний шаг, поэтому этот шум не усредняется.
3. **Доказательства.**
   - С1: МПК-A1 (EMA) − A0 (без EMA) на Slovo **+1,47 [+1,03; +1,92]**, на Bukva +0,33 [−0,06; +0,72] (не установлено). SD-5, тот же рецепт.
   - [Izm18], полный текст, с. 2: 10 эпох SWA на ImageNet — **+0,8 п.** для ResNet-50 и DenseNet-161, +0,6 для ResNet-152. На CIFAR-100 — больше 1,3 п.
   - [Wort22], полный текст, табл. 1: ViT-G, ImageNet. Лучшая модель перебора — **90,78 %**, жадный суп — **90,94 %**. Суп работает для дообучений из одной предобученной точки: у нас это веса РЖЯ.
   - [6th]: суп последних 10 эпох — в решении.
4. **Где выигрыш.** Все исполнители, по порядку величины — доли пункта или ≈ 1 п. ([Izm18], С1 на Slovo). Если в порте Sohn усреднения весов ещё нет — проверить первым. Есть ли оно — **вопрос к к2**.
5. **Угрозы.** На Bukva эффект EMA в С1 не установлен: при коротком бюджете усреднение мало что даёт. (б) работает, только если затравки дообучения начинаются с **одних и тех же** предобученных весов. В протоколе статьи 1 предобучение повторялось для каждой затравки, поэтому суп там неприменим без нового плана. С BatchNorm после усреднения весов нужно пересчитать статистики ([Izm18]).
6. **Минимальная проверка.** (а) — переоценка готовых прогонов, если сохранены контрольные точки последних эпох: на ЦП, без обучения. Иначе одно плечо LOSO. (б) — три дообучения от одних весов, суп против ансамбля по логитам. Цена: (а) — почти 0; (б) — одна серия.
7. **Взаимодействия.** Входит в U29 (б). С ансамблем U28 суп конкурирует: суп бесплатен на выводе, ансамбль ×3.

## U31. Адаптация к новому исполнителю на выводе (статистики нормализации, TENT)

1. **Механизм.** Перед оценкой исполнителя пересчитать статистики BatchNorm по M его **неразмеченным** клипам ([Schn20]). Или дополнительно один проход минимизации энтропии предсказаний по параметрам γ, β нормализации ([Wang21]). M задаётся заранее. Клипы адаптации не совпадают с оцениваемыми или это оговорено (оговорка к1, `k1_k2/0090`). Схема **трансдуктивная**, в отчёте — отдельной строкой.
2. **Какую ошибку устраняет.** Сдвиг распределения «новый человек + новая студия и камера». Это и есть LOSO (С1, разд. 4.2). Цепочка: статистики признаков у нового ведущего другие → нормализация, обученная на других, сдвигает активации → ошибки → пересчёт статистик убирает сдвиг.
3. **Доказательства.**
   - [Schn20], полный текст, аннотация: ResNet-50, ImageNet-C, mCE **76,7 % → 62,2 %** после замены статистик BN статистиками искажённых изображений. Улучшение есть и от одного примера, 32 примеров достаточно.
   - [Wang21], полный текст, табл. 2: CIFAR-10-C (самая сильная степень искажения), ошибка: без адаптации **40,8 %**, пересчёт BN **17,3 %**, tent **14,3 %**. CIFAR-100-C: 67,2 / 42,6 / 37,3 %.
   - Условия далеки от наших: искажения изображений, а не другой человек. Пакеты 64–128 примеров одного распределения.
4. **Где выигрыш.** Ожидаемо — исполнители, сильнее всего отличающиеся съёмкой: ведущие YouTube, у Sohn 25,4 % против 36,4 % на пилоте. **Оценки нет**: в пространстве нормированных точек сдвиг меньше, чем в пикселях, и перенос величин из [Schn20] и [Wang21] неоправдан.
5. **Угрозы.** (1) Клипы одного ведущего неслучайны по классам — уроки по темам. Статистики BN смещаются темой, а не только съёмкой, и tent может «схлопнуться» на частые классы. (2) Нужны слои BN в Sohn: есть ли они в порте — **вопрос к к2**. Если там LayerNorm, механизм [Schn20] неприменим, tent надо переопределять. (3) Сравнивать с обычным выводом только с пометкой «трансдуктивно». Для системы на телефоне это значит адаптацию по первым M жестам пользователя.
6. **Минимальная проверка.** На ЦП по готовым моделям Sohn ALL-UZ, без обучения: пересчёт BN по M = 32 клипам исполнителя (не из оцениваемых), затем оценка остальных. Отдельной строкой. Цена — минуты на ЦП на фолд.
7. **Взаимодействия.** С U12 (состязательное «забывание исполнителя») решает ту же задачу другим путём. При положительном U31 польза U12 может уменьшиться.
